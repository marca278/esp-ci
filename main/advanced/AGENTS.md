# AGENTS Guide

This repository is an ESP-IDF console example project with custom command components.

## Scope And Intent

- Keep edits focused on source and project config files used by this example.
- Prefer small, surgical changes over broad refactors.
- Follow existing ESP-IDF and C style in touched files.

## Project Layout

- `main/console_example_main.c`: app entry point (`app_main`) and REPL loop.
- `components/cmd_system/`: system CLI commands.
- `components/cmd_wifi/`: Wi-Fi CLI commands.
- `components/cmd_nvs/`: NVS CLI commands.
- `main/console_settings.c` and `main/console_settings.h`: console transport setup (UART/USB).
- `main/Kconfig.projbuild`: example options exposed in menuconfig.
- `partitions_example.csv`: custom partition table used by defaults.
- `sdkconfig.defaults`: baseline config for this example.

## Build, Flash, Monitor

- Configure options: `idf.py menuconfig`
- Build only: `idf.py build`
- Flash only: `idf.py -p <PORT> flash`
- Monitor only: `idf.py -p <PORT> monitor`
- Flash and monitor: `idf.py -p <PORT> flash monitor`

Replace `<PORT>` with the board serial port (for example `/dev/ttyUSB0`).

## Tests

- Integration test file: `pytest_console_advanced.py`
- Run test: `pytest pytest_console_advanced.py`
- Tests are parameterized for `esp32` and `esp32c3` targets.

## Safe Edit Boundaries

- Edit: `main/`, `components/`, `CMakeLists.txt`, `main/CMakeLists.txt`, `sdkconfig.defaults`, `partitions_example.csv`.
- Do not edit generated outputs under `build/`.
- Do not hand-edit `sdkconfig` (generated by menuconfig/build).

## Common Pitfalls

- UART is default console transport; USB transports require menuconfig options.
- Some terminals do not support escape sequences needed by line editing; see troubleshooting in README.
- Secondary serial console is output-only and can interfere with interactive workflows on USB_SERIAL_JTAG targets.
